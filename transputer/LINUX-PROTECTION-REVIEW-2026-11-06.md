# Linux protected userspace and trap-syscall rollout

Reviewed on 6 November 2026 against linux-7 `8cbf83364d85`, compiler integration `32afb1db`, and the T4 protection sources. Kernel paths below start at `transputer/linux-7/arch/transputer/`. The private experiments used the existing T4 counting emulator, the same kernel configuration and the same BusyBox, shell and fbwm. Only PID 1's syscall transport was selected differently. The two kernel/CPIO images were repacked separately.

## Reproduced release blocker

With `T4_PROTECT=1`, `CONFIG_TRANSPUTER_L_THDS_BOOT=y`, `CONFIG_TRANSPUTER_SPINE_CHIP=y` and the existing hard-P boot command line, private PID 1 builds gave these results.

| PID 1 build | Observed result |
|---|---|
| `-DTP_USE_T9K_SYSCALL=0` | BusyBox child returned and fbwm printed `DESKTOP_LOOP`. |
| `-DTP_USE_T9K_SYSCALL=1` | Ordinary P syscall traps returned repeatedly. After the first successful `/bin/true` spawn, the child ran a second time. Cause 2 ended PID 1 and Linux printed `Attempted to kill init!`. |

The debug rerun shows PID 1 resuming after `syscall` at IPtr `8080039D`. The child entered at `80900040`, WPtr `C09A7F90`, with the same PDS `804FC668` and RODS buffer `804FC694` used by PID 1. Immediately after `SPAWN_RET:00000000`, the next `goprot` reloaded that same child IPtr/WPtr. The repeated path executed privileged `STOPP` at `80003527`. This trace and the static buffers in `kernel/t9000_prot.c` identify a lost parent continuation. Both control and trap builds also reported `-EFAULT` from PID 1's raw getdents probes. Track that existing uaccess failure independently. Ubuntu evidence is under `~/tpw/desktop-integrate.H5R7uU/transport/`, including `mode1/traptrace.log`.

## Implementation order and acceptance tests

1. **Give each live P continuation its own state.** `include/asm/processor.h` embeds a soft memory map per task, but `kernel/t9000_prot.c:t9k_run_user_until_exit` fills global `soft_pds_buf[11]` and `soft_rods_buf[4]`. `kernel/process.c:__switch_to` installs the next task's map. Synchronous spawn in `kernel/syscall.c` can enter another image while the parent supervisor call is live. Save or stack PDS, RODS, address-space identity, supervisor workspace, result and restart state per live entry, including nested activations on the same task. Preserve live FPU stack, flags and rounding mode and live 2D block-move registers before supervisor use or a task switch, following ISM chapter 13 and Appendix A. **Pass when** nested child and grandchild exit, parent code resumes exactly once at the instruction after its syscall, and two alternating processes retain distinct registers, mappings, FP state and 2D transfer parameters.

2. **Define one protected syscall ABI with six arguments.** `kernel/syscall.c:tp_publish_syscall_gate` publishes a raw C entry pointer at `80000060`, the hard-P flag at `80000064`, a shared return word at `80000068`, and a pointer at `8000006C` to kernel BSS holding the call number and six arguments. `transputer/tests/syscall_stub.c:tp_t9k_trap_syscall` writes the latter block directly. The kernel guesses between that block, A/B/C and a raw workspace read; the register fallback alone supplies only the first two arguments. Give P a documented, checked call frame or register plus user-block contract. Copy arguments before dispatch, return the signed result via the saved continuation, and use a kernel-owned supervisor workspace. Route uClibc's special `mmap.c` / `__transputer_mmap2_packed` path through it too; that helper calls the C gate independently. **Pass when** all six distinct argument sentinels arrive in order, including mmap offset/flags, bad numbers return ENOSYS, bad pointers return EFAULT, libc errno and raw negative results agree, and nested callers cannot swap results. Exercise exec success and failure, child exit status and wait, blocked syscalls, EINTR and SA_RESTART without double dispatch.

3. **Handle P returns by cause.** In `kernel/t9000_prot.c:t9k_run_user_until_exit`, only syscall takes the resume path. Every successful syscall counts toward a 100,000-iteration limit. In `t9k_enter_userspace`, other nonzero results feed `do_exit(cause)`, including timeslice. `kernel/syscall.c` currently returns success for rt_sigaction/rt_sigprocmask and EAGAIN for sigtimedwait. Implement timeslice scheduling/resume, signal delivery and sigreturn, a defined repair/restart or signal policy for access faults, and controlled termination for illegal instructions. Preserve ps.Eptr versus the next IPtr. **Pass when** an ordinary process survives more than 100,000 calls; a time-sliced sibling progresses; one faulting process receives the intended signal while the supervisor and sibling survive; a restarted write does not write twice.

4. **Enforce user permissions for the whole access.** `t9k_on_exec_finish` and `t9k_soft_fill_rods` force full-quarter Q2 identity RWX (`a0000003`). Q0 can expose a writable device quarter. Q3 can remap split data/stack or mirror Q2. T4's `t9000_pmi.c:pmi_shared_ok` exempts low kernel RAM, display and several MMIO ranges. Private-deny and text-ROM checks are opt-in. Plan a representable code/data/workspace layout within four region descriptors and mediate UART, storage and display through the supervisor or explicit narrow mappings. In `include/asm/uaccess.h`, `__t9k_access_ok` asks for read permission even for a destination. In `include/asm/t9000_softprot.h:t9k_soft_ok`, the RX overlap check tests the starting address, and 32-bit end/limit arithmetic needs overflow-safe handling, including the top quarter. `mm/uaccess.c` translates the first address then copies the full count. **Pass when** P and supervisor copies reject kernel, sibling and unauthorized device ranges, writes across an RX boundary, wraparound, and execution from stack. Positive tests must cover legal split-stack buffers and the authorized framebuffer window.

5. **Test transfer paths and the two hardware contracts separately.** Current T4 word/byte accesses call `t9k_translate`. `p.c:t9k_move` checks source/destination by quarter for MOVE and DEVMOVE; MOVE2DALL checks by row and conditional variants select bytes. Fast paths need the same permission outcomes. `t9000_protect.c:t9k_probe_range` checks endpoints, which alone cannot exclude a denied interior PMI range. Test ordinary and device loads/stores, instruction fetch, wrong-type device access, cross-quarter MOVE, a transfer spanning a denied interior range, and later-row MOVE2D faults with guard bytes. On SPINE the supervisor receives reason/type in A/B and ps.Cntl holds status. The compatibility T4 path reads a cause in ps.Cntl and can clear it. `t9k_install_task_rods` still programs T4 MMIO slots, including PMI window registers. Separate emulator hooks from RTL paths, restore state via the documented ABI, and fence privileged controls from P. Run isolated-access and trap/resume tests on both T4 and RTL. A hard-P policy should fail explicitly when entry is unavailable. Today cause zero, inactive maps or disabled hard P can lead to classic L entry. Keep an explicitly selected compatibility profile for legacy images.

6. **Rebuild the userspace that actually boots.** Add one target/profile selection consumed by the stub, allocator bridge and their callers. Make stub/flag changes invalidate cached objects and bFLTs. `transputer/build.sh` builds init, tpsh, BusyBox and the shell/direct/uClibc probes. Also cover `fbwm/build-fbwm.sh`, `doom/build-transputer.sh`, `tpkg/build.sh`, `coremark/transputer/build-flt.sh`, `build-native-tcc.sh`, the ABI test runner, uClibc and dependent applications. Native TCC reuses an existing stub object; Doom can fall back to a temporary one; `packages/build-packages.sh` can ship that object. Restage packages, initramfs, BTL and SD images and check the selected executable when an SD copy takes precedence. **Release gate:** disassemble the built clients, boot a trap-only image through init, nested BusyBox, shell and fbwm with the C gate unavailable, verify the negative isolation tests, and boot an explicitly compatible legacy image separately.

The current T4 `tests/test_t9000_protect.c` host suite passed in this review, including region translation, device-only access and range endpoint checks. The desktop profile also logged the kernel soft selftest and first P entry. The tests establish emulator behavior for those cases. RTL behavior, a mixed-task isolation test, a fully trap-only rootfs, and FPU/block-state continuity remain acceptance work.
