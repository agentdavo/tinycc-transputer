# Retained-surface MOVE2D blit

`blit_surface` uses MOVE2DALL only when the build enables it, the destination
is the normal framebuffer, and the clipped source rectangle is wholly within
its slot and the reserved shared bank. This proves the blocks disjoint for
the two supported address profiles. Small rectangles and all other layouts
retain the original row-by-row copy. T414 builds leave the feature disabled.
The general `tpos_shm_blit_to_slot` path is unchanged because its source may
alias the destination. The existing slot-3 bank overflow is documented
separately in `SHM-SLOT-OVERFLOW-2026-11-06.md`.

## T800 comparison

`tests/bench/fbwm_blit.sh t800 row` and `... t800 move` build the same real
`blit_surface` source with and without `TPOS_HAVE_MOVE2D`. The benchmark uses
the fixed 320×240 source, an 800-pixel destination stride and twelve repeated
full blits. Its full-frame reference also checks negative and right/bottom
clipping, small copies, an unusual stride, an alternate destination and the
out-of-bank slot fallback. It checks source and destination contents and
reports the separate slot-3 bank canary.

| Work | Row copies | MOVE2D guard | Repetitions |
|---|---:|---:|---:|
| 320×240 | 2,107,020 | 1,918,248 | 12 |
| 16×16 | 598,803 | 413,715 | 256 |
| 32×16 | 729,875 | 544,787 | 256 |
| 64×32 | 1,884,947 | 1,425,427 | 256 |

Counts are estimated T800 cycles, not measured hardware time. Both modes
produce framebuffer hash `1979545989` and `fail 0` in the default profile;
under `TPOS_SPINE_CHIP` both produce `2659170693` and `fail 0`. In both
profiles the separate canary reports the pre-existing `slot3_overflow 1`.
Correctness also matched on T9000, T805, T800 and strict T425 emulation; the
T414 row-copy fallback compiled and passed. The host geometry and canonical
frame regression passed. Linked T800 disassembly contains only three local
loads between `move2dinit` and `move2dall`, with no intervening call or
branch.

its T800 runtime SHA-256 was
